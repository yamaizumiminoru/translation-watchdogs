# 翻訳おつかれ Watchdog 👏🍵

ChatGPT の翻訳スレッドを見守る Chrome 拡張です。

## 対応マニュアル（手動・代理操作）

画面を見て復旧する場合は、**停止せずに送れるなら、まず「続けて」を一度だけ送る**方針にします。180秒の無変化は固着を疑う目安であり、処理が終わった証拠や停止の許可にはしません。

### 1. 対象と進捗を確認する

- 指定された翻訳会話か確認し、最新の回答本文・ツール出力・エラー表示・入力欄を見ます。過去のエラーや本文中の引用だけで復旧しません。
- 本文やツール出力が実際に増えていれば待ちます。無表示停止や接続中断が疑われる場合は、原則180秒の観察で変化を確認します。点滅や経過時間の表示だけは進捗に数えません。ただし、無変化だけで裏の処理まで停止したとは断定しません。
- `[[TRANSLATION_COMPLETE]]` や全作業の完了を確認したら、再開依頼を送りません。続行不能の最終報告、ユーザーへの確認・承認待ち、ログイン待ちも、単なる固着として自動的に「続けて」で進めません。
- 既存の下書きを上書きしません。同じ最新ターンに再開依頼を送信済み・待ち行列へ追加済み・結果不明であれば、重ねて送りません。拡張機能や別の操作者との二重送信にも注意します。

### 2. 停止せずに送れるか確認する

1. 再開依頼が必要で、依頼された操作の範囲内なら、入力欄が空であることを確認して「続けて」を入力します。
2. 入力後の画面をもう一度確認します。停止ボタンが表示されていても、入力すると通常の送信ボタンが現れる場合があります。
3. **実行中の処理を止めない通常の送信**が可能なら、一度だけ送ります。送信ではなく**待ち行列への追加**が用意されている場合は、その動作を確認して一度だけ追加します。
4. ボタンの働きが不明、送信できない、または送信に中断が伴う場合は、停止や再読み込みを試さず状況を報告します。停止が必要なら、進行中の処理を中断する可能性を伝えてユーザーに確認します。

停止の承認が得られた場合だけ停止し、画面で停止を確認してから次の操作へ進みます。すでに送信・追加した依頼がある場合は、停止後も重複送信しません。許可のない停止を、再読み込みや新スレッドへの移動で代用しません。

### 3. 画面表示・保存・再開を分けて確認する

- **送信操作・画面表示の確認**：送信ボタンを一度押したこと、新しいユーザーメッセージの吹き出しや入力欄の変化を確認します。吹き出しの出現と入力欄のクリアは一時的な表示の場合があり、それだけではサーバーへの保存・送信成功を保証しません。「送信操作を行い、画面に表示された。保存・再開は未確認」と区別して伝えます。
- **待ち行列表示の確認**：画面上の待機・予約表示を確認します。その表示だけで永続的な受付や実行再開を断定しません。待ち行列の表示がない場合に、待ち行列へ追加されたと推測しません。
- **保存の確認**：正常に再取得された会話履歴に依頼が残っているなど、一時的な画面表示とは別の根拠で確認します。実行中の画面を保存確認のためだけにむやみに再読み込みせず、進行への影響と操作の許可を確認します。根拠が得られない場合は、保存未確認のままとします。
- **再開の確認**：新しい回答本文やツール出力など、実際の作業進捗を確認して初めて報告します。依頼が履歴に残っていても、接続中断表示や古い出力だけのままなら、再開は未確認です。
- 一度見えた依頼が後で消えた場合は、「画面表示は確認したが、保存・配信は確認できない」と訂正します。消失だけで未配信と断定せず、自動再送しません。送信や受付の結果が不明な場合も、依頼の表示と最新状態を確認し、必要な判断をユーザーに求めます。

復旧後も、正本は [yamaizumiminoru/translations](https://github.com/yamaizumiminoru/translations) の `main` とし、`manifest`・`checkpoint` 等を再確認して保存済みの続きから進める方針を維持します。新スレッドへの引き継ぎが必要な場合も、同じ「翻訳」プロジェクトの確認、下書き保護、一度だけの引き継ぎ、失敗時の安全停止を維持します。このマニュアル自体は、個別の停止・承認待ちの操作・新スレッド作成への許可にはしません。

## 拡張機能 v0.3.15 の現行動作

**以下は現在の拡張機能の実装説明です。上の対応マニュアルの更新だけでは、拡張機能や配布ZIPの動作は変わりません。** v0.3.15 には、180秒の無変化を検出して自動停止する処理が残っています。停止前の確認を必要とする運用では、この版の自動監視を有効にしないでください。以下の自動停止の説明を、手動・代理操作で停止してよいという許可として使わないでください。

- 監視を ON にしたスレッドだけを対象にします。
- ChatGPT の応答が完全に止まり、20秒間安定したら、労い＋再開メッセージを送ります。
- エラー表示がなくても、ツール実行履歴で途切れ、通常の回答操作欄が出ていない状態を「無表示停止」の候補として検出します。本文・ツール表示・生成状態が180秒間変わらなかった場合だけ、労い＋再開メッセージを送ります。この待ち時間は設定で変更できます。
- `[[TRANSLATION_COMPLETE]]` を検出すると自動停止します。
- 完了合図を検出すると「完訳おつかれさまでした！最後まで本当にありがとう🍻🎉」を送り、そこで監視を終了します。
- ChatGPT が「エラーのためこれ以上続行できない」と明言した場合は、「ここまでありがとう、おつかれさまでした👏🍵」を一度送り、そこで監視を終了します。
- 最大再開回数（初期値20回）で必ず止まります。
- 会話容量の上限を明示する画面文言を検出すると、同じ「翻訳」プロジェクトの新規チャットへ移り、前スレ末尾の進捗抜粋を添えて再開します。
- 永続状態の正本には [yamaizumiminoru/translations](https://github.com/yamaizumiminoru/translations) の `main` を使います。該当 `projects/<slug>/` の `manifest`、`checkpoint`、chunk inventory、QA、`manuscript/` を再取得し、`output/` は直接編集しないよう引き継ぎます。
- 通常の「接続が中断されました」の最中は、ChatGPT が応答中扱いを終えるまで待ちます。ただし、本文・ツール履歴が180秒間まったく変化しない固着を確認した場合は、停止して労い＋再開依頼を送ります。
- 一時的な接続中断・配信タイムアウトは続行不能扱いにせず、従来どおり再開対象にします。会話容量の上限もエラー終了にはせず、同じプロジェクトの新スレへ引き継ぎます。
- 特に `Message delivery timed out. Please try again.` は優先復旧シグナルです。監視開始時点ですでに表示されている場合も対象にし、初期値では5秒待ってから労い＋再開依頼を送ります。画面上の `Retry` は自動クリックしません。
- 最新のassistantターンで `Thinking failed` の失敗操作欄が表示された場合も、応答中表示が消えた後、初期値5秒間の安定を確認して労い＋再開依頼を送ります。本文中の引用や、回答操作欄のある完了済み応答は対象にしません。
- Watchdog自身の再開依頼が `Something went wrong. Please try again.` で送信失敗し、最新のuserターンに `Retry` が表示された場合は、初期値で5秒待ってから同じ送信を1回だけ自動Retryします。同じ失敗に対する自動Retryは繰り返しません。
- 最新のassistantターンのエラー欄に `Stream cache expired` または `Resume stream unavailable` と `Retry` が並ぶ場合は、入力欄の下書きを保護し、初期値で5秒待ってから画面の `Retry` を1回だけ試します。既存の下書きが別内容なら操作しません。本文内の引用、過去のエラー、Retryと離れた表示では発動しません。再開を確認できなくても同じターンへの自動Retryは繰り返しません。
- `Analysis errored` が最新の応答操作欄に出ても即送信しません。回答操作欄がなく、本文・ツール履歴が180秒変わらない場合だけ再開依頼の候補にします。
- 同じassistantターンへの自動送信は送信ボタンを押す前に使用済みとして記録し、送信結果が不明な場合も重複送信しません。
- 上記の明示的な送信失敗は、ChatGPT側に古い停止ボタン相当の要素が残っていても「応答中」より優先します。画面が生成中に見えるという誤判定でRetryを見送らないようにしています。
- 配信タイムアウトと停止ボタンが同時に残り、`Fetching...` などの点滅だけが続く場合は、本文・ツール履歴の変化を180秒確認します。変化がなければ、固着した応答を停止し、停止を確認してから労い＋再開依頼を自動送信します。点滅アニメーションだけでは進捗と判定しません。
- エラー文言が出ず、停止ボタンだけが残ったツール応答も、本文・ツール履歴が180秒変化しなければ同じ自動復旧を行います。通常の文章生成だけが長い場合は対象にしません。
- ツールの `Worked for 14m 40s` のような経過時間は進捗とみなさず、実際の本文やツール出力が変化したときだけ停止確認の時計を戻します。最後のツール出力が `Encountered exception: <class 'caas.internal.errors.ClientError'>.` で途切れ、回答操作欄がない場合も180秒の停止確認に入ります。監視開始前にこの状態になっていた応答も対象です。
- 監視開始前の通常の応答をすでに処理済みとして待つ場合は、ポップアップに「次の応答を待っています」と表示します。
- `Analysis errored` の操作欄だけが残り、assistant の本文要素が作られなかった場合も、最新のユーザーメッセージより後にあるエラー欄に限って停止候補として扱います。古いエラーや本文中の引用には反応しません。手動再開も同じ判定で使えます。
- `ClientError` または `Analysis errored` による途切れは、まず180秒の無変化を確認し、通常の「続けて」の代わりに `/mnt/data` の存在確認を一度だけ頼みます。同じツール実行を延々と繰り返さないよう指示します。
- 異なる応答でツール環境の失敗が2回連続した場合は、同じ「翻訳」プロジェクトの新スレに一度だけ自動引き継ぎします。停止ボタンが残っていれば、停止を確認してから移動します。新スレでも失敗した場合や、下書き・プロジェクトが確認できない場合は安全停止します。通常の回答が完了すると連続失敗の回数は戻ります。
- assistantが`ClientError`等でツール実行を続けられないと明示して最終回答した場合も、同じプロジェクト内への引き継ぎを一回だけ試します。通常の「続行不能なので労って終了」は、ツール環境以外の終了報告に適用します。
- 拡張機能の再読み込みで古い content script のコンテキストが無効になった場合、そのページの旧監視タイマーを直ちに終了します。`Extension context invalidated` を繰り返し記録しません。
- ChatGPTの新しい会話DOMで使われる `data-turn="assistant"` と、従来の `data-message-author-role="assistant"` の両方を認識します。画面更新で役割属性が切り替わっても、無表示停止の180秒監視を継続します。
- 新しい会話DOMの `data-turn-key` と `data-user-message-bubble` も認識します。送信失敗のRetryがユーザーメッセージに付いている場合は、古い「翻訳中」表示のまま放置しません。Retry済み判定は本文でなく安定したターンIDに結び付けます。
- ユーザー文と回答が同じ `data-turn-key` の枠に入る表示でも、検索単位の役割から両者を分けます。ユーザー文の引用や過去のエラーを、最新の回答エラーとして扱いません。
- プロジェクトの新規チャットで送信ボタンが `aria-label="Send"` の場合も検出します。既存の下書きは上書きせず、送信確認が取れない場合も自動再送しません。

## インストール

1. Chrome で `chrome://extensions` を開きます。
2. 右上の「デベロッパー モード」を ON にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. ZIPを展開したフォルダー、またはこの `chatgpt-translation-watchdog/` フォルダーを選びます。直下に `manifest.json` があることを確認してください。

拡張機能を再読み込みした直後は、開いている ChatGPT タブも一度だけ再読み込みしてください。新しい content script が入り、古い版の監視タイマーも確実に終了します。

このフォルダーから読み込む開発用の拡張は、Chromeの「更新」ボタンでGitHubの最新版を取りに行きません。新しいファイルを同じフォルダーに置いてから拡張カードの「再読み込み」を押してください。Chrome画面の「更新」で配布版を取得するには、Chrome Web Store に登録してその版をインストールする必要があります。準備と移行手順は [Web Store 配布・更新手順](../docs/chrome-web-store-update.md) を参照してください。

## 拡張機能の使い方

1. ChatGPT の「翻訳」プロジェクトで、見守りたい会話を開きます。
2. Chrome の拡張機能メニューから「翻訳おつかれ Watchdog」を開きます。
3. 「このスレを見守る」を押します。

開始時点ですでに通常完了している古い応答へは、誤爆防止のため自動送信しません。ただし、ツール実行履歴または `Analysis errored` で途切れ、回答操作欄がない「無表示停止」だけは、監視開始時点から180秒確認したうえで自動復旧します。配信タイムアウトまたはツール応答と停止ボタンが同時に固着した場合も、180秒後に停止を確認して自動復旧します。それ以外の古い応答を再開したい場合は、一度だけ「今すぐ労って続けて🙏」を押してください。

容量上限が表示されたときは自動引き継ぎが動きます。手動で引き継ぎたい場合は「新スレへ引き継ぐ↗」も使えます。

## 初期メッセージ

> ここまで本当にありがとう、おつかれさまです👏🍵　保存済みの続きからお願いします🙏
> 正本・manifest・checkpointを再確認し、未完了箇所から作業を続けてください。翻訳がすべて完了したときだけ、回答末尾に `[[TRANSLATION_COMPLETE]]` と付けてください。

完訳時には次を送って終了します。

> 完訳おつかれさまでした！最後まで本当にありがとう🍻🎉　保存と最終確認もありがとう。ここで終了です☺️

続行不能エラー時には次を送って終了します。

> ここまで進めてくれて本当にありがとう、おつかれさまでした👏🍵　エラーでこれ以上続けられない件、了解です。保存済みの状態はそのままにして、ここで止めます🙏

## 安全策

- 対象は `https://chatgpt.com/` だけです。
- 容量上限の新スレ作成は、元スレと同じプロジェクト slug を URL で検証します。
- 新スレの入力欄またはページタイトルに設定済みのプロジェクト名「翻訳」が見つからない場合、送信せず停止します。
- 送信完了を確認できない場合、自動再送しません（重複防止）。
- 拡張機能は会話本文を外部サーバーへ送りません。設定・回数・引き継ぎ用の末尾抜粋は Chrome のローカルストレージ内だけに置きます。
